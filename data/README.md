# Data

**Every file under this directory is synthetic. No record describes a real person.**

The contents of `raw/` and `processed/` are gitignored: they are large, fully regenerable,
and not source. Only this file and the `.gitkeep` placeholders are tracked.

## Why there is nothing here yet

The project materials supplied a *Dataset Guide* — a tiered list of where to legally
obtain NHS-suitable data. They did not supply a dataset. See
[`../docs/data/dataset-strategy.md`](../docs/data/dataset-strategy.md) for the full gap
analysis and the reasoning behind what follows.

## Provenance

| Directory | Source | Licence |
|---|---|---|
| `raw/` | [Synthea](https://github.com/synthetichealth/synthea) FHIR R4 bundles | Apache 2.0 |
| `processed/` | Synthea output with a UK identity overlay, plus this project's operational generator | This project |

Synthea models a patient's lifetime clinical history. It does not model a hospital's
operations, so roughly half of what this project needs — appointment slots, clinician
rosters, appointment outcomes, bed occupancy, waiting times — has no open source at all
and is generated by `backend/scripts/generate_operational_data.py`.

## Regenerating

```bash
docker compose exec api python scripts/import_synthea.py --count 200
docker compose exec api python scripts/generate_operational_data.py --weeks 12
docker compose exec api python scripts/seed_demo.py
```

Both scripts are deterministic under a fixed `--seed`, so a dataset can be reproduced
exactly for debugging or for a demo.

## How synthetic data is kept identifiable as synthetic

Three levels, none of which can be bypassed by forgetting a convention:

1. Every generated row carries `data_origin = 'SYNTHETIC'`.
2. Every API response derived from it carries `"dataOrigin": "SYNTHETIC"` in `meta`.
3. The frontend renders `<SyntheticDataNotice />` whenever it sees that value.

Generated contact details use reserved ranges so a bug cannot reach a real person:

| Field | Range | Why |
|---|---|---|
| Email | `*@example.test` | RFC 2606 reserved TLD — undeliverable |
| Phone | `+44 7700 900xxx` | Ofcom drama range — reserved for fiction |
| NHS number | `999 000 0000`–`999 999 9999` | Test range, Modulus 11 valid. **Verify against the NHS Data Dictionary** (open action D2) |

## What must never be placed here

Real patient data, pseudonymised NHS extracts, or any DARS-supplied dataset — regardless
of how well anonymised it is believed to be. Per the golden rule in the supplied Dataset
Guide, real data enters a project only once a DPIA, a Data Sharing Agreement and
Information Governance approval are actually in place, not "in progress". None exist for
this project.
